# Dense W4AFP8 GPTQ for the Hopper CUTLASS kernel

**Decision.** Expose kernel-aware INT4 selection as an opt-in experiment tied to the target serving layout. The stock quantizer and the served GEMM disagree on a reproducible weight. Changing GPTQ to use the served reconstruction lowered exact held-out KL on two Qwen3 sizes. ARC-Easy accuracy moved in opposite directions even on one model when only the calibration sample changed. One physical row-parallel shard also reverses the preferred code.

## From saved scale to a real GEMM

1. Main observes BF16 group scales, solves with those scales and writes fake-quantized weight carriers. The explicitly packed exporter quantizes these to signed codes and encodes eight biased nibbles `q+8` per INT32 word. The checkpoint retains BF16 group scales. [Observer](https://github.com/vllm-project/llm-compressor/blob/18b10e2d7269e332c05eef4dda52adf74c08872e/src/llmcompressor/observers/base.py#L99) · [GPTQ](https://github.com/vllm-project/llm-compressor/blob/18b10e2d7269e332c05eef4dda52adf74c08872e/src/llmcompressor/modifiers/gptq/gptq_quantize.py#L34) · [writeback](https://github.com/vllm-project/llm-compressor/blob/18b10e2d7269e332c05eef4dda52adf74c08872e/src/llmcompressor/modifiers/gptq/helpers.py#L126) · [exporter](https://github.com/vllm-project/compressed-tensors/blob/7be5968f0b64dfe73a189f0cf128f17c0a9c06ca/src/compressed_tensors/compressors/pack_quantized/base.py) · [packing](https://github.com/vllm-project/compressed-tensors/blob/7be5968f0b64dfe73a189f0cf128f17c0a9c06ca/src/compressed_tensors/compressors/pack_quantized/helpers.py) · [upstream example](https://github.com/vllm-project/llm-compressor/blob/18b10e2d7269e332c05eef4dda52adf74c08872e/examples/quantization_w4a8_fp8/llama3_example.py)
2. The W4A8 loader computes `c = max(row_max(s)/448, 1/(448*512))` on the rank's resident groups. Group factors are `f = E4M3(E4M3(s/c)/8)`, with FP32 channel multiplier `8*c`. CUTLASS repacks signed weights, looks up the rounded product and uses dynamic per-token FP8 activations. For a unit basis vector the decoded weight is `E4M3(q*f) * (8*c)` before BF16 output rounding. [Scheme](https://github.com/vllm-project/vllm/blob/62d4bc3c7e33b1b6c906e233e6af2d3506c482ca/vllm/model_executor/layers/quantization/compressed_tensors/schemes/compressed_tensors_w4a8_fp8.py) · [scale conversion](https://github.com/vllm-project/vllm/blob/62d4bc3c7e33b1b6c906e233e6af2d3506c482ca/vllm/model_executor/layers/quantization/utils/quant_utils.py) · [CUTLASS load and apply](https://github.com/vllm-project/vllm/blob/62d4bc3c7e33b1b6c906e233e6af2d3506c482ca/vllm/model_executor/kernels/linear/mixed_precision/cutlass.py)
3. With group scales [0.75, 1.0] and weight −2.59375, stock GPTQ picks −3 and produces −2.140625. Kernel-aware selection picks −4 and produces −2.859375. Across 32,768 fixture entries (repeated rows), 2,560 strictly improve. For weight −2.5625, −4 also wins globally. Loading the first 128 of 256 columns as one row-parallel shard gives outputs −2.140625 for −3 and −3.0 for −4. The original −3 then wins. This is single-shard operator evidence. ## Exported model A/B

Both GPTQ arms use 16 × 128 identical WikiText train tokens, symmetric g128, block 128, damp 0.01, minmax scales, no actorder, and original activations at subsequent layers (`propagate_error=False`). The prototype feeds the served reconstruction into GPTQ error propagation within a linear, and exports the selected nibble with the original BF16 storage scale. Replacing only the stock block implementation with QDA's non-aware block produced 702/702 bit-identical tensors on 0.6B. The aware builds change packed weights only. Every quantized quality run loaded the exported checkpoint in stock vLLM on the same H100, TP1, dense `CutlassW4A8LinearKernel`. The same 128 held-out WikiText test paragraphs (seed 727) provide 9,355 teacher-forced positions. KL is teacher-to-student, all vocabulary logits, per position, from FP32 log-softmax with FP64 KL accumulation. All extracted target-token log probabilities agreed with vLLM's public API within 0.000005. At calibration seed 13 the percentile 95% intervals for the paired GPTQ KL change are [−.03642, −.01330] and [−.04364, −.01253] using 10,000 paragraph resamples. ARC-Easy used all original test questions, zero-shot full-answer-text log likelihood without length normalization. The aware arm gained/lost 231/315 answers on 0.6B and 171/127 on 4B (paired exact McNemar p=.00037/.01261). With seed 42 on 0.6B, changing only the calibration paragraphs retained the KL improvement (95% interval [−.02895, −.00491]) and flipped the ARC effect to +113 correct (335 gained, 222 lost, p=.00000193). The two seed trials illustrate sensitivity and do not estimate the average over calibration sets. Each time and memory figure comes from one build per arm. Serialized weight-file sizes match within each model (538,459,960 and 2,651,839,568 bytes). **Contribution boundary.** An explicit dense Hopper CUTLASS target can justify the choice of reconstruction in the solver. General default enablement would need task evidence across models and a defined sharding policy. A loader or backend whose basis outputs contradict the predicted levels falsifies this implementation for that target. A paired holdout showing no KL benefit would weaken the quality case even if the operator identity holds. The immediate serving test beyond this study is a full two-rank row-parallel model run comparing a checkpoint targeted to that layout with the TP1-targeted export.

## Reproduce

Use Python 3.12 in separate quantization and serving environments. Quantization used NVIDIA PyTorch `2.14.0a0+4fdf77b940.nv26.8.63802676`, Triton `3.8.0+git4c7e62b7.nv26.8`, transformers 5.24.0, datasets 5.0.1 and compressed-tensors `0.20.2a20261123`. Install this checkout editable with `pip install --no-build-isolation --no-deps -e .` in a matching quantization environment. Serving used stock vLLM 0.34.0, torch 2.14.0+cu130, transformers 5.22.0, compressed-tensors 0.17.0 and pyarrow 26.0.1. H100 80 GB driver 580.126.20. Quantization and serving shared the physical W4AFP8 GPU. TinyMoE used a separate idle H100. Triton, Inductor, CUDA and vLLM caches were study-specific, with the installed FlashInfer cache warm. Full teacher-logit caches need roughly 6 GB per model.

Set `QPY` and `VPY` to the two Python executables. Set `QDA` to the read-only QDA snapshot and `BENCH` to the fork timing checkout linked above (with history containing its README corpus). Set the following to local snapshots or parquet files. The scripts validate weight and corpus hashes.
